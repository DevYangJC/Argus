# 国内镜像源配置指南

## 一、为什么需要配置国内镜像源

在国内服务器部署 Argus RAG 时，Docker Hub、Elastic 官方镜像仓库、GitHub Release 等外部资源经常会出现访问慢、连接超时、TLS 握手失败、镜像拉取中断等问题。部署过程中最常见的表现包括：

- `docker compose pull` 长时间无响应；
- `docker compose up -d --build` 拉取基础镜像失败；
- 构建 Elasticsearch 自定义镜像时，插件下载失败；
- 同一条命令偶尔成功、偶尔失败，部署过程不稳定。

因此，建议在国内服务器上优先配置可用的镜像加速或代理服务，降低首次部署和后续更新时的网络不确定性。

## 二、当前推荐镜像源

当前项目部署可以使用你正在使用的镜像源：

```text
https://xuanyuan.cloud/
```

它主要用于改善 Docker 公共镜像的拉取速度，例如：

- PostgreSQL；
- MinIO；
- Elasticvue；
- 其他来自 Docker Hub 的公共镜像。

需要注意的是，Docker 镜像源主要影响 Docker 镜像拉取。对于 Dockerfile 内部执行的普通网络下载，例如 Elasticsearch IK 插件下载，仍然可能需要单独处理。

## 三、配置 Docker daemon 镜像源

在 Linux 服务器上编辑 Docker daemon 配置文件：

```bash
sudo mkdir -p /etc/docker
sudo nano /etc/docker/daemon.json
```

写入以下内容：

```json
{
  "registry-mirrors": [
    "https://xuanyuan.cloud/"
  ]
}
```

如果你的服务器已有 `/etc/docker/daemon.json`，不要直接覆盖原文件，应把 `registry-mirrors` 合并进去。例如已有日志配置时，可以写成：

```json
{
  "registry-mirrors": [
    "https://xuanyuan.cloud/"
  ],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
```

保存后重新加载并重启 Docker：

```bash
sudo systemctl daemon-reload
sudo systemctl restart docker
```

确认 Docker 正常运行：

```bash
sudo systemctl status docker
docker info
```

在 `docker info` 输出中可以查看是否出现 `Registry Mirrors` 配置。

## 四、本项目中的使用方式

进入部署目录：

```bash
cd /opt/argus-rag/Argus-backend/deploy
```

服务器 A 拉取公共镜像：

```bash
docker compose --env-file .env.server-a -f server-a.compose.yml pull
```

服务器 A 启动并构建自定义镜像：

```bash
docker compose --env-file .env.server-a -f server-a.compose.yml up -d --build
```

服务器 B 拉取和启动：

```bash
docker compose --env-file .env.server-b -f server-b.compose.yml pull
docker compose --env-file .env.server-b -f server-b.compose.yml up -d --build
```

如果你不是使用完整项目路径，而是在服务器上只放置了独立部署目录，例如：

```text
myRag/
├── env/
├── images/
└── server-a.compose.yml
```

则进入该目录执行同样命令即可：

```bash
cd /path/to/myRag
docker compose --env-file .env.server-a -f server-a.compose.yml up -d --build
```

## 五、Elasticsearch Dockerfile 的额外注意事项

当前服务器 A 中 Elasticsearch 使用自定义 Dockerfile：

```text
images/elasticsearch/Dockerfile
```

内容类似：

```dockerfile
FROM docker.elastic.co/elasticsearch/elasticsearch:8.15.3

RUN bin/elasticsearch-plugin install --batch https://get.infini.cloud/elasticsearch/analysis-ik/8.15.3
```

这里有两个网络访问点：

1. `FROM docker.elastic.co/elasticsearch/elasticsearch:8.15.3`
   拉取 Elasticsearch 基础镜像。

2. `RUN bin/elasticsearch-plugin install ...`
   在构建阶段下载 IK 中文分词插件。

Docker 镜像源通常只能改善镜像拉取，不能保证第二步插件下载一定成功。如果构建时报 IK 插件下载失败，可以考虑以下方案：

- 多重试几次 `docker compose ... up -d --build`；
- 更换 IK 插件下载地址；
- 在服务器上提前下载插件包，再修改 Dockerfile 使用本地文件安装；
- 将构建好的 Elasticsearch 镜像推送到自己的私有镜像仓库，部署时直接拉取。

## 六、常用验证命令

查看 Docker 镜像源配置：

```bash
docker info | grep -A 5 "Registry Mirrors"
```

测试拉取一个小镜像：

```bash
docker pull hello-world
```

查看 Compose 服务状态：

```bash
docker compose --env-file .env.server-a -f server-a.compose.yml ps
```

查看启动日志：

```bash
docker compose --env-file .env.server-a -f server-a.compose.yml logs -f
```

只查看 Elasticsearch 构建或启动日志：

```bash
docker compose --env-file .env.server-a -f server-a.compose.yml logs -f elasticsearch
```

## 七、常见问题

### 7.1 配置了镜像源但仍然拉取失败

先确认 Docker 是否重启成功：

```bash
sudo systemctl restart docker
docker info
```

如果 `docker info` 中没有出现镜像源配置，通常是 `/etc/docker/daemon.json` 格式错误。可以用下面命令检查 JSON：

```bash
python3 -m json.tool /etc/docker/daemon.json
```

### 7.2 `docker compose pull` 只拉取镜像，不启动容器

这是正常行为。`pull` 只负责提前下载镜像，不会创建或运行容器。真正启动服务应执行：

```bash
docker compose --env-file .env.server-a -f server-a.compose.yml up -d --build
```

### 7.3 自定义 Dockerfile 构建仍然慢

这通常是因为 Dockerfile 内部还有额外下载动作，例如 IK 插件下载。镜像源只能解决一部分问题，插件、安装包、脚本下载需要根据具体 URL 单独处理。

### 7.4 重启 Docker 会不会删除容器数据

不会。`sudo systemctl restart docker` 只重启 Docker 服务，不会删除镜像、容器和数据卷。真正会删除容器的是：

```bash
docker compose down
```

真正会删除数据卷的是：

```bash
docker compose down -v
```

`down -v` 会删除数据库、Elasticsearch、MinIO 等持久化数据，生产环境不要随意执行。

## 八、建议

国内部署建议把镜像源配置作为服务器初始化的一部分，在执行任何 `docker compose pull` 或 `docker compose up` 之前完成。对于 Argus RAG 当前部署结构，镜像源能明显改善 PostgreSQL、MinIO、Elasticvue 等公共镜像拉取体验；Elasticsearch 自定义镜像还需要额外关注 IK 插件下载是否稳定。
